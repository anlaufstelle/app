{% load i18n core_tags %} {% comment %} Dynamische ``data_json``-Felder, gruppiert nach FieldGroup (M0/P4, Refs #1056). Seit M2/P3 (Refs #1058) entity-neutral: gerendert wird allein aus ``data_form`` (einer :class:`core.forms.dynamic.DynamicDataForm`), damit Client/Case dieselbe Feldfläche nutzen können. Der Event-Pfad erreicht dieses Partial über den Shim ``core/events/partials/dynamic_fields.html`` (Pfad-Stabilität für ``EventFieldsPartialView``, ``events/create.html``, ``events/edit.html``). Kontext-Keys: - ``data_form`` — PFLICHT; darf auch ``None`` sein (dann wird nichts gerendert). - ``existing_attachments`` — OPTIONAL, nur Bearbeiten-Flows: ``{slug: [entry, ...]}`` für die Datei-Ersetzen-/Soft-Delete-Steuerung (#622). Fehlt der Key (Anlage-Flow), bleibt der Attachment-Block leer. M24/AP4 (Refs #1738, ADR-039): Der frühere Kontext-Key ``event`` ist entfallen. Anhänge hängen jetzt an Ereignis, Person ODER Fall; jeder Entry trägt seine ``download_url`` selbst (``services/attachments.attachment_download_url``), das Partial kennt den Owner-Typ nicht mehr. Rendert je Gruppe eine Sektion via ``data_form.grouped_blocks``. Gruppen-Header erscheinen nur, wenn benannte Gruppen existieren — ohne Gruppen bleibt die Darstellung flach (eine „Felder"-Sektion, wie zuvor). Einklappbare Gruppen (``is_collapsible``) tragen die CSP-kompatible Alpine-Komponente ``collapsibleGroup`` (nur benannte Property-/Methoden-Pfade, keine Inline- Expressions/Argumente; Startzustand via ``data-start-open``). Bedingte Feldlogik (M1/P5, Refs #1057): Der Wurzel-``
`` liegt IM HTMX-Swap-Ziel ``#dynamic-fields`` (create.html), trägt das E12-Payload als ``json_script`` (nur wenn Bedingungen existieren) und die delegierten input/change- Listener. Jedes Feld sitzt in einem ``conditionalField``-Wrapper (``x-show="visible"``, liest den globalen ``fieldConditions``-Store). Beim DocType-Wechsel ersetzt HTMX den Wurzelknoten samt Payload — ohne Payload leert der Evaluator den Store (alles sichtbar), sodass ein neuer DocType nie Sichtbarkeiten des vorherigen erbt. CSP-strikt: nur die Komponentennamen, ``x-show="visible"`` und ``data-field-slug`` als Ausdrücke. Gruppen-Sichtbarkeit (Refs #1867): Sind ALLE Felder eines Blocks (benannte Gruppe ODER die Ungruppiert-Karte) Bedingungs-Ziele, liefert ``block.condition_slugs`` eine kommagetrennte Slugliste (``dynamic.py:grouped_blocks``) — die Karte wird dann zusätzlich in ``
