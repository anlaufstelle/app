{% load i18n %} {% comment %} Interaktives Feld-Board (M0 P6/P7 + #1713, Refs #1056/#1058) — DAS zentrale HTMX-Swap-Ziel `#field-board`. Jede Board-Mutation (Feld zuordnen/entfernen, Gruppe anlegen/umbenennen/löschen, Drag-and-Drop-Sortierung) ersetzt diesen Container per outerHTML. Globale Block-Sequenz (#1713): Gruppen UND ungruppierte Felder sind Top-Level- „Blöcke" in EINER Reihenfolge (im Service via iter_blocks_in_order vorbereitet, NICHT hier sortieren). Es gibt keinen fixen „Ohne Gruppe"-Block mehr — freie Felder sitzen als eigenständige Top-Level-Zeilen zwischen den Gruppen. Drag-and-Drop (P7, config-sortable.js): * `data-sortable="blocks"` umschließt ALLE Top-Level-Blöcke (Gruppen-Karten mit `data-group-id`, freie Feldzeilen mit `data-dtf-id`; beide tragen `data-block` und einen `.drag-handle`). Block-Reorder-URL in `data-reorder-url` (config_reorder_blocks), Move-URL in `data-move-url` (config_move_field, für den Gruppe→Top-Level-Zweig). * je Gruppe eine `data-sortable="fields"`-Liste (`data-group-id`, Felder-Reorder- URL in `data-reorder-url`, Move-URL in `data-move-url`); jede Feldzeile trägt `data-dtf-id` + `.drag-handle`. Die Nicht-Doppelaktivierung der verschachtelten Sortables beruht auf dem SortableJS-dragEl-Guard (innere Liste bubbelt zuerst), nicht auf disjunkten Handles. Das Sortable wird NICHT im Template initialisiert (kein Inline-JS). Kontext: doc_type, blocks (Liste aus {"kind":"group","group":g,"fields":[...]} | {"kind":"field","field":dtf}), add_form (DocumentTypeFieldAddForm), group_form (FieldGroupForm). {% endcomment %}
